## 3. CHED/DepEd Compliance Validator (`compliance_validator.php` with views `validate_curriculum.php`, `compliance_rules.php`, `compliance_references.php`; `compliance_actions.php`; `ComplianceValidationService`)
1. **Works end to end for what exists.** Run on the clone for a test program version with its one rule (`MIN_TOTAL_UNITS` 20): HTTP 201, a stored run with `rules_evaluated 1, failed 1`, a result row with a snapshot of the rule, reference and actual value, and a `COMPLIANCE_VALIDATION_RUN` audit row. For BSIT (no rule) it returned 200 with "No active rules from verified references apply to this curriculum version." and stored nothing. The runner is deterministic PHP (no AI).
2. **Permissions and audit.** `compliance.view`, `compliance.manage`, `compliance.run`, `compliance.reference.verify`; CSRF; read scope through the shared check. Verified: Acad Faculty 403/403; Acad Office and Staff can view and run (201). Run, reference and evidence changes are audited. **Layout: old** (`compliance-context-grid`, own autocompletes, no shared bar, no `csms-*` components, domain tables).
4. **Rules, evidence, claims.** Five rule types are encoded: `MIN_TOTAL_UNITS`, `MAX_TOTAL_UNITS` (sum of mapped subject units), `REQUIRED_SUBJECT`, `MIN_SUBJECT_UNITS`, `MAX_SUBJECT_UNITS`. Rules are **data** (rows in `compliance_rules`, entered by a user). A rule is evaluated only if it is active and its reference is `verified`; every result carries the reference as `[type] code — issuing body` plus the stored source URL. "Verified" is an internal assessment: it can only be set through a recorded, confirmed document-identity evidence event (tested: setting `verified` directly is refused with that message) and the UI states it is not CHED certification. Results are PASS, FAIL or NOT_EVALUATED (for example a subject-unit rule whose subject is not mapped). The code never reports compliance without a rule and a verified reference; with none it says so. **However the repository contains no real CHED CMO or DepEd rule**: only `DEV-DEMO` synthetic rules (marked "NOT A REAL CHED, DEPED, OR BESTLINK POLICY") and test fixtures. The CHED CMO 25 material exists only as graduate-outcome mapping data used by the Export, explicitly "not compliance evidence".
5. **Defects.** Blocker for a defense that promises CHED/DepEd checking: no real rule set is seeded or documented (the validator is an empty engine until someone enters rules from real memoranda). Should fix: unit totals sum every mapped placement including electives, with no required/elective distinction; old layout; no automated test; a rule applies per program or curriculum, not per version or level. Cosmetic: three-way page naming (`validate_curriculum.php`, rules, references).

## 4. Curriculum Export Tool (`curriculum_export.php`, `curriculum_print.php`; `export_actions.php`; `CurriculumExportService`)
1. **Works end to end for CSV.** Preview returned 52 subjects; `download_csv` returned 200, `text/csv; charset=UTF-8`, `attachment; filename="BSIT_BSIT-DEMO-2026_PREORAL-2026.csv"`, 34,923 bytes, 100 lines. It starts with a UTF-8 BOM and the header `Program Code, Program Name, Curriculum Code, …, Placement Type`; data rows are the selected version's placements (CC101, CC105, CCS1102/CC102 …; CC104, CC106 and DM102 all present; 52 mapped in the database), followed by the optional outcome, CLO, requirement, elective, weighting and compliance sections. CSV injection protection and CRLF are handled (`tests/csv_export.php`). A failed build leaves no audit row.
2. **Permissions and audit.** `curriculum_export.view` plus a review-state rule (`curriculum_export.official` for approved versions, `.draft` otherwise). Verified: Acad Faculty and Acad Office 403, Staff preview 200 and CSV 200 on a draft version, guest 401, CSRF required for the download. `CURRICULUM_EXPORT_GENERATE` is audited for CSV and for the print view. **Layout: current**: the only one of the four on the shared Program > Curriculum > Version bar.
3. **PDF and password protection.** There is **no PDF generation on the server** (no library; no PDF, spreadsheet or archive action: `pdf`, `download_pdf`, `download_xlsx` return 400 "Unknown action"). "Print / Save as PDF" opens `curriculum_print.php`, an HTML page that triggers the browser's print dialog; the PDF, if any, is made by the user's browser and is unprotected. **Password protection does not exist, not even as a prompt**: the words password and confidential appear nowhere in the export page, script, print page or service, and extra `password`/`passphrase`/`pdf_password`/`protect` parameters are simply ignored. The generated CSV was inspected: plain UTF-8 text, not a ZIP, not encrypted. PHP 8.0.30 here has the `zip` extension with `ZipArchive::setEncryptionName`, so an AES-encrypted ZIP is possible without any new library; a real encrypted PDF would need a PDF library (none installed, no Composer).
5. **Defects.** Blocker (against the stated requirement): no real PDF and no password protection of confidential reports. Should fix: no HTTP regression test for the endpoints; the CSV carries no draft or confidential marker in the file itself.

### Update 2026-11-12: slice E1 built (password protection for the CSV export)
- **What:** the CSV tab has a "Protect with password" option (password and confirm fields, minimum 10 and maximum 128 characters, clear messages, `csms-info` explaining which tools open the file). When chosen, `download_csv` returns `application/zip` named `<program>_<curriculum>_<version>_protected.zip`, an AES-256 (WinZip AES, method 99) archive made with `ZipArchive` containing the CSV. Unprotected export is unchanged.
- **Password handling:** POST with CSRF only (a GET is refused); validated first; used once in memory; removed from the request array; temporary archive has a random name unrelated to the password and is deleted in a `finally`; no log, audit row or URL receives it (tested against the database, the server log and the source). The audit row (`CURRICULUM_EXPORT_GENERATE`) records actor, program, curriculum, version, `format: csv_zip_aes256` and `protected: true`, nothing else.
- **Which tools open it:** 7-Zip, WinRAR and WinZip. Windows File Explorer cannot open AES-encrypted ZIPs, as far as we know (it supports only the older ZipCrypto); this is stated in the page and was NOT tested on a Windows Explorer in this audit. Archive Utility on macOS also does not support AES.
- **Tests:** `DB_NAME=sms_db_uitest php tests/export-protected-http.php` (50 checks, disposable schema): the ZIP is AES (method 99, encrypted flag), plain CSV text appears nowhere in its bytes, no password / wrong password / almost-right password cannot read it, the right password opens it, the content equals the plain CSV, six invalid-password cases are rejected (422) with no audit row, a role without export rights gets 403, guest is refused, CSRF is required, GET is refused, an exporter role with draft rights can export a draft version, and the password appears in no table, no response header and no server log. Also green: `tests/csv_export.php`, `tests/ui-consistency-static.cjs`, JS and PHP syntax.
- **Still missing:** a real server-side PDF (E2), the CSV carries no draft or confidential marker inside the file, and no regression tests for the unprotected download beyond the new test's basic checks.

### Real PDF without Composer: options (analysis only, nothing built)
| Option | Fit | Effort | Notes |
|---|---|---|---|
| **FPDF** (one PHP file plus a small font folder, permissive license; confirm the license text when vendoring) | Good for a table report | about 1 day | Latin-1 text only: map UTF-8 to cp1252 (dashes, accents, quotes need handling). No encryption of its own, which is fine if the PDF goes inside the encrypted ZIP. |
| **TCPDF** (a folder of files, no Composer needed; LGPL) | Full UTF-8 and built-in AES encryption (`SetProtection`) | 1-1.5 days | Large (several MB), slower, LGPL obligations to check. PDF encryption mostly opens in common readers, but the permission flags are advisory. |
| Dompdf or mPDF | Best HTML-to-PDF | not realistic | Need Composer and many dependencies. |
| Hand-written minimal PDF writer | Possible | 1.5-2 days | Fragile, own font and table code to maintain, no encryption without writing RC4/AES. Not recommended. |
| Headless browser (`chrome --print-to-pdf` of the print page) | Looks identical to the print view | 0.5 day to prototype | Needs a browser on the server, not available on typical shared hosting, process-launch security concerns. Not recommended. |

**Could the PDF go in the same encrypted ZIP?** Yes. A ZIP can hold several entries and `ZipArchive::setEncryptionName` encrypts each one with AES-256 using the same password, so one protected download could contain the CSV and the PDF. That also means the PDF library does not need to implement encryption.

**Recommendation:** FPDF for a plain tabular PDF (one vendored file, about a day), delivered inside the same AES-256 ZIP when "Protect with password" is on, and as a plain PDF otherwise. Choose TCPDF only if the panel needs full Unicode text or PDF-level encryption. Needs your decision before it is built.

### Update 2026-11-12 (later): slice E2 built (real PDF + page redesign)
- **PDF:** `download_pdf` on the export endpoint, same permission gate, CSRF, scope filters and audit as the CSV. FPDF 1.86 is vendored unmodified in `shared/lib/fpdf/` (not `vendor/`, which is git-ignored) with `LICENSE.txt`, a `NOTICE.md` line (permissive licence, no usage restriction) and an `.htaccess` deny rule; it also needs its four Helvetica metric files in `font/`, so it is one library file plus those. `CurriculumPdfRenderer` draws the PDF from the SAME dataset array as the CSV and the preview: title, program, curriculum, version, status, effective year, scope, generated date, a table grouped by year and semester (Code in the shared code blue, Title wrapped, Units, Type), semester and year totals, total subjects and units, header on later pages, footer "Generated from stored curriculum data (draft/approved status as shown)" and "Page N of M". No approval claim. UTF-8 is mapped to Windows-1252 (en dash, quotes, accents kept; invalid bytes and unmappable characters become "?", never an exception). A real 52-subject BSIT version renders in about 6 ms as 3 pages.
- **Protection:** with "Protect with password" ticked the PDF goes inside the E1 AES-256 ZIP (`<name>_pdf_protected.zip`); no PDF-level encryption. Audit: `format` `pdf` or `pdf_zip_aes256`, `protected`, and now also `scope` on every export row.
- **Page:** tabs, the Export Scope card, the Generate button, the "Entire Curriculum" chip and the duplicated status lines are gone. Under the shared context bar a panel (`csms-panel`, `csms-empty` until a version is chosen) shows the curriculum name with ONE summary line (version, subject and unit counts, scope), a `csms-filter-row` with the Year and Semester/Term `csms-select`s plus Download CSV, Download PDF and a secondary Print, one shared "Protect with password" (fields cleared after a download, same 10-128 rule, `csms-info` about 7-Zip/WinRAR/WinZip), and the live preview. The preview loads automatically when a version is selected (it is a handful of SELECTs, about a second at most), so no Generate button is needed. Dead tab, scope-card and format-card CSS was removed; no new CSS was added.
- **Tests:** `tests/export-protected-http.php` now 95 checks, including: valid PDF (`%PDF-`, `%%EOF`, page count above 0), subject codes and total units equal to the database and to the CSV, accents and en dash mapped, unmappable characters safe, year and semester scopes change CSV and PDF equally, protected PDF needs the password, 403/401/CSRF/GET refusals, audit rows (actor, program, curriculum, version, scope, format, protected), no password anywhere, and the new page structure.
- **Still open:** the print view is still the browser's print of an HTML page (not changed); the CSV carries no draft marker; the layout of the new panel at 1440, 1024 and 390 px and the PDF in a real viewer have not been looked at by a person.
