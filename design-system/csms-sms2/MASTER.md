# CSMS-SMS2 Design System — MASTER

Status: **draft for user review**. Advisory only; `docs/ui-reference/UI_Decisions.md` (D1–D8) wins on any conflict.
Stack: plain PHP, Bootstrap 5.3 (custom Sass, compiled CSS committed), vanilla JS, Bootstrap Icons. Tokens live in `assets/ui/scss/_variables.scss`.

## 0. How this was produced
- `ui-ux-pro-max` `search.py` could not run (Python is not installed; only Microsoft Store stubs exist). The skill's CSV data in `~/.claude/skills/ui-ux-pro-max/data/` was read directly for the domains ux, color, typography, style and chart instead of running `--domain` searches with `--density 8`. No `--persist` was used, so nothing was generated by the script.
- Skill inputs actually used: UX guidelines (navigation, active state, deep linking, breadcrumbs, focus states, keyboard navigation, contrast, color-only, form labels, error placement, skip links); color rows "Grant / Funding Portal" and "Research Lab / University Department" (institutional navy `#1E3A5F`, slate neutrals, red destructive) as evidence that an institutional navy palette fits; style "Accessible & Ethical" and "Minimalism & Swiss"; chart accessibility guidance.
- Rejected, not adopted: dark glassmorphism, green accent, serif headings, web fonts.

## 1. Style
Quiet, airy, flat. White cards on a light page background, thin borders, no shadows, no gradients, no glass effects. Function first; decoration only where it carries meaning.

Rule: every text/background pair ≥ 4.5:1; large text and UI boundaries ≥ 3:1. Re-measure any new pair before use.

### Typography (self-hosted/system only)
- Family: `system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", sans-serif` for body and headings (one sans font, D5).
- Scale: base 16px; h1 24px/600; h2 20px; h3 18px; tables, menus, form labels, `.small` 14px; badges and sidebar section headings 12px (the floor, D6). Nothing below 12px.
- Line height 1.5 body; numerals in clocks and tables use `tabular-nums`.

### Spacing and shape
- 4px base grid; common steps 4, 8, 12, 16, 20, 24, 32. Card padding 16×20. Content padding 20×24, bottom 80px to clear the floating CIMF button (D8).
- Radius 6px. No shadows. Layout widths: sidebar 280px, topbar 56px, context bar ≥ 44px.

## 3. Sidebar (D5, D7)
- Navy background, white 14px items. Groups in this order: **Workspace**, **Curriculum**, **Setup**. No number badges, no demo box.
- Section headings: 12px, bold, uppercase, `#c9d4f2` (6.99:1).
- Exactly one active style everywhere: `rgba(255,255,255,.18)` fill, 600 weight, 3px white inset bar on the left, `aria-current="page"`.
- Sub-items share one indent (34px) with no icon; groups collapse via Bootstrap collapse, open automatically when a child is active.
- Labels wrap at spaces only (`word-break: normal`); long names such as "Academic Strand/Course Assignment" never split mid-word.
- Items shown only if the user holds the same permission the legacy sidebar checks.
- Below 992px the sidebar slides off-canvas behind a menu button (Esc closes).

## 4. Header (D1)
Holds only global items: menu toggle (mobile), clock, user avatar link. Notifications are listed in D1 but no feature exists, so none is rendered. **Never** put program/curriculum/version selectors in the header. Sticky, 56px, white, bottom border.

## 5. Compact context bar (D1–D4)
- Only on pages that depend on a curriculum version; sits directly under the page title (dashboard shows a read-only context line, not a selector).
- One row, about 44px, sticky just below the topbar. Small 14px labels beside three small selects: Program → Curriculum → Version.
- One "Reset" link replaces three × buttons.
- When all three are chosen the bar collapses to one line `BSIT / BSIT-DEMO-2026 / PREORAL-2026` plus a "Change" link (focus moves to the first select).
- Cascade: each choice narrows the next list; next dropdown opens automatically; auto-pick when exactly one option; last choice remembered for the session; selection placed in the URL as `?program=&curriculum=&version=` so pages are linkable. Works without JS as a GET form.
- Wraps to two rows on narrow screens; never hides selects.

## 6. Page header
Breadcrumb above the title (14px), then h1, then one-line subtitle in secondary text. Primary page actions right-aligned on the title row. Breadcrumb is `nav[aria-label="Breadcrumb"]`, last item `aria-current="page"`.

## 7. Cards
White, 1px `#dfe4ee` border, header with an h2-level (18px) title and an optional small link-out icon (`bi-box-arrow-up-right`, must have an accessible name). No nested cards.

## 8. Tables
- 14px text, header row 600 weight on `#eef1f7` (9.11:1), row padding 8×12, compact variant 5×8.
- Hover highlight only; striping off by default. Numeric columns right-aligned with `tabular-nums`.
- Wrap in `.table-responsive`; use `<caption class="visually-hidden">`, `<th scope>`; sticky header for long lists.
- Row actions: icon + text label or `aria-label`; destructive action last and in danger color with a confirm modal.
- Empty state: one sentence plus the primary action. Loading: spinner or skeleton, never a frozen table.
- Pagination or "showing X of Y" for lists over ~50 rows; show counts next to headings (e.g. "52 placements", D8).

## 9. Forms
- Every control has a visible `<label for>` above (or beside, in the context bar); placeholder is a hint only.
- Required fields marked with `*` plus "required" text for screen readers.
- Validate on blur and on submit; inline error under the field, red text with an icon, linked by `aria-describedby`; a summary `role="alert"` for submit failures.
- Disable the submit button and show a spinner while saving to prevent double submit.
- Filter bars: single compact row of 14px controls, "Reset" link on the right, applied filters visible; no duplicate controls for the same filter (D8: one year filter only).
- Use correct `type`/`autocomplete`. Destructive confirmations in Bootstrap modals with focus trapped and returned.

## 10. Status colors
Status is never color alone: badge = tinted background + dark text + icon + word.
| Status | Badge | Icon |
|---|---|---|
| Active / Approved / Compliant | success tint | `bi-check-circle` |
| Draft / In review / Pending | warning tint | `bi-hourglass-split` |
| Rejected / Non-compliant / Error | danger tint | `bi-x-circle` |
| Info / Reference | info tint | `bi-info-circle` |
| Archived / Inactive | neutral `#e9ecf2` + `#374151` (8.71) | `bi-archive` |
CIMF output is always labelled "AI suggestion · Human review required" (advisory only).

## 11. Focus and interaction
- Every interactive element has a visible focus ring: 3px outline, ≥ 3:1 against its surroundings (white on navy in the sidebar, navy-tinted `.35` ring on light surfaces). Never `outline: none` without a replacement.
- Full keyboard operation; tab order follows visual order; skip-to-content link on the shell (to add with the pilot page).
- Click/tap for primary actions (no hover-only). Touch targets ≥ 32px high on desktop UI, ≥ 44px on mobile; 8px minimum gap.
- Motion: ≤ 200ms, transform/opacity only, honour `prefers-reduced-motion`.
- Icons: Bootstrap Icons only; icon-only buttons need `aria-label`; decorative icons `aria-hidden="true"`.

## 12. Charts (when needed)
Prefer a table or bar chart; use pie only for ≤ 5 parts with direct labels. Palette from the status/primary tokens above, with labels, patterns or direct value labels so color is never the only cue. Always supply a data-table fallback and a text summary. No charts are required for the pilot.
